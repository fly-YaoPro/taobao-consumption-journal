# 淘宝交付验收

## 数据与叙事

- 核对用户授权账号、指定范围或默认十年、实际覆盖年份。抽查单商品、多商品、部分退款、未知金额，父订单去重与实付不重计，不重复扣退款。
- 订单ID字符串不丢精度，数量为正整数，币种和金额原标签可核对。订单数不混商品件数，不均摊未知的类目金额。
- 确实无订单、未读取、失败三种状态分开，覆盖四年不写十年完整，最早可见订单不当注册日。
- 总览≤200字，主题约40—100字，有1—3组可回查来源；下单日不当使用日，节日逐年核对，不凭商品推婚育/健康/关系/职业。
- 不添加影视人物、人格匹配或与消费回看无关的入口；标题沿用用户选择。

## 视觉

- 首页保留有内容价值的模块，不要求全部出现。物件、阶段、跨年区不能重复同一发现；阶段按有据变化划分，无变化不强编，不把年度数量与采集状态当人生阶段。
- 实看一张完整大文件夹和两张滚动交叠的状态：标签、白色叙事纸、商品相纸、侧笺清晰；正文与来源不可遮挡。过高面板自动转正常文档流，手机与减少动态效果时不叠层。
- 阶段标题自然断句，正文、侧笺、图注不重复同一段话；日历来源定位后能回到原来的阅读位置。
- 逐图分类检查：促销海报留原图入口，不成为放大相纸；实物、封面、设计预览与服务摘要呈现有区别。原图、短名、派生图和来源对应，处理不改变商品。必须包含数字商品、服务订单、长标题与广告图的复杂样本，不只测干净摄影。
- 全年、首次、增减与生活事件逐条核对覆盖和证据；不能把漏采写成消费减少。说明集中收起，不在每页反复放免责声明。

按 [动态拼贴固定框架](scrapbook-blueprint.md) 制作，实际打开本地参考图辅助核对配色、纸层和物件关系，再于桌面与手机检查总览、主题、日历和计划。首页大标题、不同大小的真实相纸、可读便签，下方主题文件夹和底部三入口导航；不能交付普通卡片资料页。三种主题确有不同排法，解释不左右复制。商品图逐一可追溯到订单、核对过的对应商品页或用户授权实拍；规格一致，不使用AI/卡通/相似商品替图，缺图明确。不用广告大图代替，不发棕做旧。

手机标题/日期→主图组合→总结→偏好，正文不缩小，导航不挡内容，三个板块统一。参考图只取视觉，不复用账号、数字和订单。

## 功能

页面制作按 [页面框架说明](implementation.md) 构建。额外跑 `node --test scripts/test_framework.cjs` 与 `python -B scripts/test_build_journal.py`，不能将脚本通过当视觉通过。

- 首次进入计划已有具体、有依据的小行动，不是空表单或购物清单，不按类目机械生成一排整理任务。无排期依据可暂不排期，编辑、过滤、备份恢复须测试空月份。
- 左总结绑定 `story.overview.text`，不是范围/失败说明；商品组合有大小层级。日历首选有记录月份、显示真实图或短标题，导航、翻页、分享不互相覆盖。

1. 首页文件夹点击与键盘打开，展开后的A/B/C叙事、返回首页、前后翻页、页码、目录、首尾状态和板块位置恢复。动效开启时正文不遮挡；减少动态效果时内容直接显示；底部导航、翻页、来源、计划操作不重叠。
2. 点订单日期能看全部已收录订单及商品，大图与原入口可核对；年月跳转正确，未读/失败非空白无订单。
3. 搜索/品类筛选跨全部已收录年份，不能只筛当前月；来源点击定位具体订单并返回主题。
4. 计划新增/修改/删除、刷新恢复、导出、按ID合并冲突和恢复备份均实际测试；不因导入丢手动版本。
5. file://双击并禁外网测试，静态浏览、搜索、日历、计划仍可用；原订单外链需要网络与权限，说明例外。
6. 分享弹窗有实际拼贴预览；真下载1080×1440PNG，包含对应商品图片而非全是文字。大标题、纸张、便笺与主页面同风格，图片与范围同源；核对用户要求，不带无关账号、地址和订单号。检查图片加载失败时不补画、不谎称成功。
7. 中断后续跑不重抓重计，图片可单独补；没有地址、手机号、聊天、凭据或浏览器profile进入交付。
