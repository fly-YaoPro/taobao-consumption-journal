# 按素材类型呈现

真实图是证据要求，选图和排版是另一道工作。先打开候选图片，看清主体、促销文字、清晰度与商品对应关系，再决定展示方式；不要按订单顺序取前三张。

| kind | 适用素材 | 页面呈现 |
| --- | --- | --- |
| object | 清晰实物主体；可用核对过的裁剪或透明抠图 | 无统一相纸边框，大小错落，准确短名 |
| photo | 原平台实际场景图或授权同商品实拍 | 少量相纸；不得假扮用户生活照 |
| cover | 核对过的书籍、唱片、游戏等真实封面 | 封面册页／小书架，不展示激活码促销海报 |
| design | 对应字体、模板、设计资源的可用原商品预览 | 素材纸页／样本卡，不用价格广告当主图 |
| service | 服务、票务、订阅等无适合实体照片的订单 | 普通摘要卡：短名、下单日、原图入口；不是官方票证 |
| source | 已实际查看的广告、文字密集或确实不适合展示的低清图片 | 小型来源摘要，不在主画面嵌入广告图 |

未分类不等于source：选入页面的图必须先看图、填story.visuals；缺映射会停止构建，不能把下载了的所有图片默默变成文字卡。promotional 为 true 且无干净派生图时，构建器仍降为来源摘要。服务／来源卡仍能查看原图，日历保留原始图片和完整商品标题。

原图已下载不代表页面已展示。核对每个item.image_path实际指向对应文件、每个展示路径对应其source_ids、派生图也被复制。只改文件名、存在HTML/空响应或没有绑定路径，都不能报下载成功。首页有可用实物/照片/封面/设计预览时至少实际展示一件，不能全部藏在日历。全部素材确实不适合放图时，才填写story.image_fallback_reason说明看图结论与缺口；不批量把普通商品图改为source来通过。

找不到干净封面或预览就用来源摘要，不向图库或 AI 借相似图。不做虚假的电影海报、登机牌、签证、使用照或个人项目成果。日期明确是下单日，不伪装成出发时间。

## 登记在 story.json

visuals 以订单里的原图相对路径为键，所有选择由 Agent 完成：

```json
{
  "visuals": {
    "images/item-a.jpg": {"kind":"object","title":"准确的实物短名"},
    "images/banner-b.jpg": {"kind":"source","title":"一份模板资源","promotional":true},
    "images/service-c.jpg": {"kind":"service","title":"某次票务订单"},
    "images/cover-d.jpg": {"kind":"cover","title":"核对过的作品名"},
    "images/raw-e.jpg": {
      "kind":"object","title":"同一商品短名",
      "display_path":"derived/item-e.png","treatment":"cutout"
    }
  }
}
```

短名不超过24字，通常6—14字；规格影响识别时保留，不把商家SEO长标题和促销词搬到主页面。完整标题与原图不删除。

派生图仅允许 crop（裁剪）或 cutout（抠图）：必须来自映射键对应原图，保留原图供放大核对。不生成、补画或改变商品，不改颜色、规格、配件；裁剪不能隐藏重要差异。抠图不可靠时保留真实照片或转来源摘要。构建器检查路径与声明，不能证明像素对应，Agent须逐图回看。

首页优先挑3—5个有代表性的素材，一件主物、几件辅助物，可混合实物、封面、服务摘要。只有一张图时用单主物布局，不以空白凑拼贴。

文件夹可用主物＋小卡、两件对照、来源条目＋一件主物。stages[].arrangement 可选 spread、ledger、contrast；未指定时交替使用。不为形式混入无关订单。无可用图可显式设 image_paths 空数组，只用叙事与来源。

构建输出media-report.json记录下载原图、已分类、可展示、首页实际图片槽位数；它只验证绑定，不证明浏览器能解码或语义分类正确。最终仍实际打开图片，检查img.complete且naturalWidth>0和画面可见，不能以文件数量代替实图验证。

最后用包含广告、数字商品、服务订单和长标题的复杂素材做本地检查。干净演示照片只验证版式，不能证明真实采集素材效果。真实测试材料不得进入公开仓库。
