# 页面框架与内容生成

`assets/starter/` 提供可运行的 HTML/CSS/普通 JS，`scripts/build_journal.py` 负责将规范数据与内容组装为离线网页。淘宝的当前视觉是 [动态拼贴固定框架](scrapbook-blueprint.md)，由 `scrapbook.js` / `scrapbook.css` 与包内字体实现；优先接入数据，不从空白另写一套。它们不替代账号访问、采集、核验或内容整理。

## 在完整流程中的位置

```text
确认目标与授权 → 采集真实资料 → 规范化与核验 → 撰写回顾和计划 → 构建页面 → 实测交付
```

本文件面向执行任务的 Agent。用户从零开始时，先按采集参考完成对应平台的数据与图片采集；不要求用户先准备数据、运行脚本或手写 JSON。用户主动提供导出时，可以从规范化阶段接入。

## 数据准备与构建

1. 按平台数据规范保存 `project_meta.json`、`coverage.json`、`records.json`（微博）或 `orders.json`（淘宝）以及真实图片。数据来自本次采集或用户提供的导出，格式转换、来源核对和缺口记录由 Agent 完成。
2. 从记录中选出有依据的细节、主题与代表图片，编写下方约定的 `story.json`，包括回顾、节点和计划建议。不要把内部数据准备工作转交用户逐项填写。
3. 实际打开所选风格的参考图，使用框架生成输出目录：

```bash
python scripts/build_journal.py --source "项目数据目录" --output "手账输出目录" --skin paper
# 微博磨砂使用 --skin frosted；淘宝使用 --skin collage
```

4. 模板不依赖 npm、运行时 AI、fetch 或 CDN。构建器使用 Python 3.9+ 标准库，将准备好的内容写入 `journal-data.js`；原始记录与展示层分开保存。构建器只负责页面组装，不承担平台采集或替用户编写经历。
5. 完成后检查桌面、手机、离线与交互，再交付完整文件夹。输出目录应为空，避免覆盖原始资料和用户内容。

## 可选：导入、续采和改版

仅在用户提供已有资料、要求续采或改版时，读取现有项目并按当前任务决定复用或补采范围。不同来源的数据先核对格式、日期、ID与图片，不执行导出包中的未知脚本。

修改既有网页时保留原始资料与手动计划。旧网页 localStorage 不一定能跨路径继承，应先导出计划再适配合并；不能承诺自动恢复或静默覆盖。这个分支不改变从零使用时的完整采集流程。

## 内容先于页面

沿用数据约定，在 `story.json` 加以下字段（示意字段，不能把示例当用户经历）：

```json
{
  "overview": {
    "headline": "根据具体记录写的一句短标题",
    "text": "200字以内的个人回顾，有具体物件、时间或原话，不是覆盖情况报告。",
    "note": "可选，一句和总览不同的短批注",
    "tags": ["有证据的短标签"],
    "source_ids": ["真实来源ID"],
    "image_paths": ["images/真实图片.jpg"],
    "image_captions": {"images/真实图片.jpg": "短图注"}
  },
  "themes": [{
    "id": "稳定主题ID", "title": "具体主题", "text": "短记",
    "range": "实际时间范围", "layout": "A",
    "source_ids": ["真实来源ID"], "image_paths": ["images/真实图片.jpg"]
  }],
  "findings": [{"title": "具体发现", "text": "一句有证据的观察", "source_ids": ["真实来源ID"]}],
  "stages": [{
    "id": "稳定阶段ID", "label": "阶段短标签", "title": "这段时间，重心变了。",
    "title_lines": ["这段时间，", "重心变了。"],
    "text": "约70—140字的阶段叙事，基于真实订单和已确认背景。",
    "source_ids": ["真实来源ID"], "image_paths": ["images/真实图片.jpg"],
    "notes": [{"title": "另一个小观察", "text": "一句短注，不复述阶段正文。", "source_ids": ["该阶段内来源ID"]}]
  }],
  "threads": [{
    "id": "跨年线索ID", "title": "仍在延续的具体事物", "text": "不同于阶段总结的观察。",
    "source_ids": ["真实来源ID"], "image_paths": ["images/真实图片.jpg"]
  }],
  "milestones": [{"title": "一个具体节点", "text": "短注，不重复整段总结", "source_ids": ["真实来源ID"]}],
  "plans": [{
    "id": "稳定建议ID", "title": "一件能做的小事", "month": "2027-03",
    "reason": "根据哪段真实记录提出；月份为可调整的建议，不冒充用户承诺。",
    "source_ids": ["真实来源ID"], "done": false
  }]
}
```

示例中的年份不是固定要求：按用户要求，未指定用执行年份下一年。`song` 沿用原规范；歌名、歌手、依据核对后再写。`url` 可选，仅用可信歌曲页面；不伪造播放按钮或音源。

淘宝首页选有代表性的不同素材，通常3—5件即可，不按订单顺序取图。先按 [素材类型](media-selection.md) 填 `story.visuals`：object/photo/cover/design/service/source。未分类和未处理促销图默认显示来源摘要，不放大成照片；原始图留在日历和放大入口。可用 display_path 加 crop/cutout 指向同原图的派生素材，构建时一同复制，不能生成替换。

`image_paths:[]` 明确表示该段用文字和来源呈现，不再自动补前三张图。`themes[].teaser` 写一句引子，`home:false` 可只留详情入口。同一发现给相同 `claim_key`；与阶段/跨年线索共用键的主题不重复出现在首页。阶段与跨年区共用 claim_key 或正文完全重复会被阻止；语义重复仍由 Agent 逐段检查。

阶段不超过6个，跨年线索不超过4个；上限不是目标。阶段可选 arrangement 为 spread/ledger/contrast，改变主物、订单条目与对照的比例。title_lines 可指定自然断句；range/period_label 从来源日期生成。图片与 notes 校验来源。

阶段可用 `detail_theme_id` 关联一个现有主题，详情必须补新信息。若使用用户确认的生活背景，在 project_meta.json 保存 confirmed_context，再以 context_ids 引用。没有背景就不填，不造经历。stages/threads 都可省略；无变化不强编阶段，代码不再把主题自动重画成阶段。

`headline` 优先5—9字，`note` 一句话，不把200字总览放成巨型标题。Agent自行整理JSON，不让用户填技术字段。跨订单分析见 [分析规则](order-analysis.md)。

### 回顾为什么有人味

- 先挑 **3—5个真正具体的细节**，再写它们之间的联系。微博用原话、前后变化、反复出现的人事物；淘宝用具体物件、复购、消费反差。每个观察都留来源。
- “从银川到北京”需要原文支持；“买了签证服务”不能写成“签证办下来了”。不猜性别、职业、关系、健康或使用体验。
- 少用“日子有了颜色”“慢慢走答案自会出现”等可放进任何人页面的结尾。可以不升华，也不把所有主题强行写成成长。使用目标账号第一人称须确认原文归属，不能替别人发明内心独白。
- 覆盖范围、接口失败和统计口径进下方说明，不占主总结。证据限定在来源入口说明一次，不在每个主题末尾重复“买过不等于用过”。敏感私密商品不默认放总览、主题或分享，仍可保留在本地原始档案。
- 图片由 Agent 筛选清晰、构图可用、能代表该主题的真实素材；无需为了占满年份把每年的第一张自拍都摆上首页。广告字很多的商品图片降为来源，不默认当主视觉。

### 计划必须先生成，不能空着

Agent 在构建期生成少量具体、可选、可编辑的建议，关联来源，不能为凑数编造愿望。构建器遇到空计划会停止，不交付空页面。无时间依据时 month 使用空字符串，页面显示暂不排期；月份不是必填。

- 微博：原文明确想做但未完成的事优先；其次根据持续兴趣提出小行动。例：多次记录同一路线的照片，可建议整理一份地点相册；不能捏造“明年旅行”或健康目标。
- 淘宝：从具体发现提出下一步，可尝试使用已有材料、补记确认过的经历、比较旧物；整理/盘点须确有价值，不逐类目重复套用。不把“又买过”写成“应该再买”，不自动定预算。
- 每条只写一个动作，依据独立显示。不随机指定月份，不由购买日推断周期、到期日或消费需求。
- 离线页面不能重新调用模型；建议在构建期写好，页面只负责呈现和编辑。“自动生成”不等于运行时写泛化随机清单。

## 已写好的版式

- **paper**：紧凑双页、居中的纵向书脊、相纸/便签/歌曲、具体节点。没有顶端装订空场，不靠大段 margin 撑版。
- **frosted**：低饱和色域、半透明面板、黄橙高亮、时间线。无缝线、金属环或旧纸。
- **collage**：大标题混合媒介拼贴、物件故事、整页文件夹、跨年线索与收尾按内容取舍。字体、自然断句、桌面叠层和手机顺序阅读已实现；不改成统计看板，不为模块齐全编故事。
- 淘宝 A：主物＋短记；B：两件对照；C：来源时间线＋主物。主物可以是实物图、照片、封面、预览或普通摘要卡，不全套相纸。C的 source_labels 可按来源ID给准确短名；完整标题仍在订单详情。每页解释只写一次。微博原 paper/frosted 用途不变。
- 日历默认最新**有已收录记录**的月份、默认选有记录的日期；格内有真实缩略图或原文短标题，右侧当日记录。空月份保留真实空态，不为了好看填假日常。跨年搜索，分页展示结果。
- 淘宝底部是固定物件式三入口导航，正文预留桌面140px/手机124px，通知也避开底栏；翻页、来源和计划按钮不得被盖住。其他皮肤沿用文档流导航。对话框可键盘关闭；来源文本经安全文本渲染，不执行商品标题中的HTML。减少动态效果设置下内容直接可见，不依赖悬停才能操作。
- 计划默认显示已有建议，支持增删改、完成、浏览器保存、JSON导出、合并前备份与恢复；同ID保留当前手动版。旧格式不匹配时先适配，不能静默覆盖。
- 淘宝分享PNG与主页面同风格：大标题、真实商品拼贴、短便笺和少量发现；弹窗先预览，再下载1080×1440 PNG，不是文字报告。构建器将所选真实图片编码为 share_images 数据URL，本地双击时不用 fetch 或外部图片，可直接画入canvas。原始订单不改写，不默认暴露地址、账号或订单号；按用户要求使用图片。微博 paper/frosted 保持原分享方式。

## 验收要记录事实

运行原数据检查器和 `node --test scripts/test_framework.cjs`、`python -B scripts/test_build_journal.py`。再实际打开页面检查1440×900、390×844：

1. 总览绑定的是 `overview.text`，不是 `coverage_note`；日期从来源计算，不手填假年份。
2. 主题不用固定大高度、巨量留白或空图占半屏；A/B/C是真的不同排法；长文有展开。
3. 日历首屏有正确年月、真实记录，格子不会撑满一整屏却看不到详情；不同覆盖状态不混成“无记录”。
4. 首次打开计划已显示具体建议；编辑/完成后刷新，导出/同ID冲突导入/恢复均测试；运行时无模型也能用。
5. 页面无横向溢出；导航、翻页、分享不相互遮挡；弹窗外正文不被永久覆盖。用截图与参考图对照，不只看结构检查绿色。
6. 双击 file:// 测试离线，实际下载PNG检查尺寸。只测localhost不能声称双击已验证。
7. 用促销广告、服务订单、数字商品和长标题做一次复杂素材检查：广告不冒充主图，服务卡不伪造票证，短名不挤满纸页；只用干净图片不算通过这项。

不要自行写“完美”“全部功能通过”。列明已测和未测。模板是可靠起点，不保证模型的内容选择正确，Agent仍须读数据、选图、写回顾与核验。
