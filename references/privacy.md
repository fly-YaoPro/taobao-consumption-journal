# 隐私筛选：先排除，再写回顾

订单里不愿被别人看到的东西，不靠页面遮罩或分享图打码解决。默认将明确私密商品及用户指定记录排除出整份展示产物；源数据仍保留在用户本地，不删除、不覆盖。

## 默认范围

- 内衣、内裤、文胸等贴身私密衣物，以及成人用品、避孕和私密健康相关商品，默认不进入回顾、主题、发现、计划、日历、搜索、分享图或可部署数据包。
- 普通袜子、外套、鞋等不因泛化关键词被排除。不要用“成人”“胸”“袜”“健康”这类单字/宽泛词扫整个文件；依据商品名称、规格、品类与实际图片判断。自动规则只是一道辅助检查，不能声称能识别所有商品。
- 用户明确说不展示的记录，无论是不是上述品类，都排除。不替用户判断“这不算敏感”。排除请求落实到稳定的订单 ID 或订单＋商品 ID，由 Agent 维护，不让用户填写技术表格。
- 一单多商品中有私密或指定排除项时，当前构建器保守地整单不导出。这样避免保留总额、标题、链接或旧叙事间接泄漏。用户仍可在本地原始资料核对，不从剩余商品反算隐藏消费。

## Agent 的执行顺序

1. 原始资料和网页输出分开放置。采集缓存、原图、完整 `orders.json`、账号资料只留原始资料目录。不要把原始资料目录打包、托管或发给协作者。
2. 在生成内容前逐条复核商品名、规格和品类；逐图查看拟展示的图片。结合用户偏好确定可展示范围。隐晦名称、组合商品、药品、贴身服饰或拿不准的图片先排除/待确认，不猜用户健康、性别或生活情况。
3. 默认将已确认要排除的记录写入本地 `privacy.json`，或在规范记录的订单/商品上标记 `exclude_from_export:true`。`privacy.json` 只在源目录，不复制到产物。
4. **仅基于留下来的可展示记录**重新撰写总览、阶段、主题、发现、计划、图注及歌曲说明。不要保留私密订单的概括性暗示，也不要在页面写“你有多少笔成人用品订单”。普通原始记录可以保留，私密记录在展示包中不留占位卡。
5. 构建器会再次做高置信关键词和显式排除检查。若旧叙事引用被排除的来源，即使还引用其他正常来源，也会停止。由 Agent 重读安全记录、重写相关段落并重建；不自动删掉来源后继续沿用旧结论，不把 JSON 修复劳动交给用户。未被引用的排除图片映射会清理。
6. 原始数据不改；输出的 `orders.json`、`orders.js`、`story.json`、`journal-data.js`、日历/搜索数据和图片均来自筛选后的白名单。未被使用的原图、下载缓存、隐藏字段不顺带复制。检查 `privacy-report.json`，再实测日历、搜索、大图和分享。

本地排除配置示例（ID 由 Agent 替换成实际数据，不当成真实订单）：

```json
{
  "exclude_order_ids": ["某个真实订单ID"],
  "exclude_items": [
    {"order_id": "某个真实订单ID", "item_id": "该单某个真实商品ID"}
  ]
}
```

配置中的 ID 对不上本地记录会停止，不能把排除要求悄悄忽略。构建日志只报通用原因，不打印商品名、图片路径或具体排除清单。完整排除判断只在用户本地处理。

## 交付和上线

筛选后的产物仍可能包含个人生活线索，**不等于自动获得公开授权**。提示用户只查看安全预览即可，不要求把原始订单交给机构/客户核查。上线前先完成逐条语义和图片复核，再明确上传范围、谁可访问，取得用户确认。默认推荐“上线”也不能自动上传；工具无受控访问能力时须单独说明。

旧网页的 localStorage 手动计划可能含旧私密描述。构建器按隐私策略版本和排除订单集合生成独立存储 key；只有隐私边界改变时隔离旧版本计划，正常新增安全订单、调整初始建议不会改变 key。已清洗产物再次构建时沿用原隐私指纹。旧计划不删除，只是不自动迁入变更后的隐私范围。不要直接把旧计划备份导入可公开的新页面；Agent 在本地审阅后只迁移用户愿意保留的内容。用户在新页面手工输入或导入的文字不能由离线构建器重新审查，分享前仍需确认。全量原始备份与清洗后的交付包须分别命名和保存。

元数据与覆盖说明采用字段白名单，嵌套日期只输出起止日期，覆盖状态仅允许固定枚举，原自由备注不随包复制。标题、回顾、图注、已确认背景等正式展示文案仍需 Agent 语义审阅；没有敏感词不代表安全。若已排除订单，旧的无来源歌曲说明也须重新核对并关联安全来源。

演示数据的 `synthetic_demo:true` 必须保留为严格布尔值，并在元数据和覆盖说明中标明“虚构演示：合成日期和订单、AI 商品图，非真实账号采集”。隐私清洗不得把演示素材洗成真实采集资料；真实任务不设置该标记，也不得把字符串当布尔值推断。

截图或商品图可能没有任何敏感文字，商品名也可能用暗语、品牌或编号。本地规则不执行图像识别/OCR；即使校验全绿也不能跳过逐图检查。同字节图片别名会被拦截，但改了裁切、压缩或水印的同一敏感图仍可能不同，须由 Agent 识别并排除。普通袜子维持正常，只有具体内容或用户要求证明其私密时才单独排除。

自动检测存在漏识别和误判，人工/Agent 语义复核、用户预览与明确部署授权三步都保留。此规则控制展示和导出，不承诺法律意义上的匿名化，也不承诺零泄漏。
